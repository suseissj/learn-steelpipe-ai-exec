# Block 4: 공개

> **Phase A 시작 시 그대로 출력한다:**
> ```
> 📖 공식 문서: https://docs.github.com/ko/pages/getting-started-with-github-pages/creating-a-github-pages-site
> ```

## EXPLAIN

### 1. 정의

| 용어 | 뜻 |
|---|---|
| GitHub 저장소 | 결과 파일을 올려 두는 온라인 폴더 |
| GitHub Pages | 저장소의 `index.html`을 누구나 열 수 있는 웹 주소로 보여 주는 기능 |
| 공개(public) | 주소를 아는 누구나 볼 수 있다. 한 번 퍼지면 되돌리기 어렵다 |

### 2. 공개해도 되는 것 / 안 되는 것

| 공개해도 된다 | 공개하면 안 된다 |
|---|---|
| 실습용 가상 데이터와 그 분석 결과 | 실제 생산량·불량률·원가·판가 |
| 일반적인 AI 도입 방법과 90일 로드맵 틀 | 거래처명·수주 단가·투자 계획 |
| '실습용 가상 데이터' 표기가 있는 보고서 | 비밀번호·토큰·사내 시스템 주소 |

### 3. 왜 공개까지 해 보나

임원이 "웹 주소 하나로 보고서를 공유하는 경험"을 직접 해 보면, 사내 보고 방식을 바꿀 때 무엇이 쉽고 무엇을 지켜야 하는지(보안·공개 범위) 판단할 수 있다. 실제 회사 자료는 사내 저장소나 private로 같은 방식을 쓰면 된다.

## EXECUTE

아래 프롬프트를 붙여 넣으라고 안내한다.

```
steelpipe-ai 결과를 GitHub Pages로 공개해 줘.
1. 공개 전 점검: index.html 과 out 폴더 파일에 '실습용 가상 데이터' 표기가 있는지, 회사명·비밀번호·토큰·개인정보가 없는지 확인해 보고한다.
2. 올릴 파일은 index.html, out 폴더, data 폴더뿐이다. env_check.txt는 올리지 않는다.
3. 저장소 이름 steelpipe-ai-report 로 public 저장소를 만들기 전에 나에게 공개해도 되는지 한 번 묻는다.
4. 내가 승인하면 git으로 커밋해 올리고, main 브랜치 루트로 GitHub Pages를 켠다.
5. Pages 주소를 보여 준다.
6. 비밀번호를 묻거나 입력하지 않는다. 로그인이 필요하면 일회용 코드만 보여 준다.
```

사람이 직접 하는 일:
1. 공개 여부를 묻는 질문에 승인한다. 망설여지면 승인하지 않아도 된다 — 그 경우 강사 시연으로 대신한다.
2. 1~2분 뒤 Pages 주소를 휴대폰이나 브라우저로 열어 보고서가 보이는지 확인한다.

### 확인할 것 (Phase B)

- `gh repo view steelpipe-ai-report`로 저장소가 public이고 `index.html`이 올라가 있는가
- `gh api repos/{owner}/steelpipe-ai-report/pages`로 Pages가 켜져 있고 주소가 나오는가
- 올라간 파일에 `env_check.txt`가 없는가

Pages가 아직 404면 1~2분 기다린다. 계속 안 되면 후속 프롬프트: "Pages 빌드 상태를 확인하고 실패 원인을 찾아 줘."
